# repair 루프 결과 — θ 튜닝으로 feasible 해 개선 (prob_1, 100블록)

빡빡하게(θ↑) 풀면 원본 다각형 위반이 생김 → **위반 블록만 보수적(θ0) 마스크로 재배치**해
실행가능하게 되돌리는 repair 루프. θ에 따라 "밀도 이득 vs 수리 비용" 균형이 달라진다.

## 결과 (모두 shapely 정확검증 통과 = feasible)

| 설정 | 풀이 obj | 위반 | 재배치 블록 | **최종 feasible obj** |
|------|---------:|-----:|-----------:|----------------------:|
| θ0 (안전 baseline) | 1,085,094 | 0 | — | **1,085,094** |
| **θ0.1 + repair** | 223,011 | 16 | **4** | **576,370** ⭐ 최선 |
| θ0.25 + repair | 88,341 | 65 | 27 | 1,767,648 |

- **θ0.1 + repair = 576,370** : 안전 baseline 대비 **약 47% 개선된 feasible 해**.
- 최종 목적 내역(θ0.1): Z1=17(지연), Z2=89, Z3=406.

## 해석 — sweet spot은 중간 θ

```
θ0.25 (과빡빡): 위반 65 → 27블록 재배치 → 수리비용 폭발 → 1.77M  (baseline보다 나쁨)
θ0.10 (적당) : 위반 16 → 4블록만 재배치  → 밀도이득 유지     → 0.58M  (최선)
θ0.00 (헐렁) : 위반 0  → 수리 불필요      → 지연 많음         → 1.09M
```
θ를 올리면 조밀 배치로 지연(Z1)이 주는데, 너무 올리면 되돌릴 위반이 폭증한다. **θ0.1 부근이
"밀도 이득은 얻고 수리는 가벼운"** 균형점 → repair가 순이득을 낸다.

## 남은 격차 (→ 1499)
576k의 대부분은 여전히 **Z1=17 (17×29091≈494k)**. 즉 재배치로 뒤로 밀린 소수 블록의 지연.
다음 레버:
- **최소변위 repair**: 전면 재배치 대신 겹친 블록을 몇 칸만 밀기 → Z1 급감 기대.
- **θ 자동탐색**: 인스턴스별 최적 θ(위반 소수) 자동 선택.
- **Z3 유도(⑥)**: 선호 베이 유도로 Z3(=406) 축소.
- 여전히 남는 최종 밀도는 NFP/연속기하.
