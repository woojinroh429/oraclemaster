# 스케줄-우선 파이프라인 실험 (prob_38) — 정직한 반증

리서치가 지목한 스케줄-우선(Layer1 CP-SAT 스케줄 + Layer2 비트엔진 실현)을 prob_38로 검증.

## 데이터 정정
- 사용자 실제 achieved Z1 = **2359** (obj 아님, 지연 그 자체; 여러번 측정).
- 이전 fallback 측정(154,774)은 **C++없는 굶주린 실행이라 무효**.
- 일관성 확인: area 하한 177 ≤ **achieved 2359** ≤ width 완화 13,381. ✅

## 결과
| 단계 | 값 |
|------|----|
| Layer-1 CP-SAT 스케줄 목표 Z1 | **187** |
| Layer-2 비트엔진 실현 Z1 | **7,151** (feasible=FALSE) |
| 사용자 achieved (NFP) | **2,359** (feasible) |
| 하한(area) | 177 |

## 결론 (반증)
- **스케줄링은 병목이 아니다** — Layer-1 목표 187로 낮음.
- **병목은 패킹 품질(Layer-2)** — 크루드 realizer 7,151 >> 사용자 NFP 2,359 (3배 나쁨, 게다가 infeasible).
- 즉 사용자의 튜닝된 ALNS+NFP가 어려운 부분(조밀 패킹)을 이미 잘함. 크루드 스케줄-우선으론 못 이김.
- 애초 "고밀도 Z1 lock-in" 진단은 잘못된 fallback 데이터 기반이었음. 정정.

## 유효한 다음 방향
- 크루드 realizer 교체가 아니라: **Layer-1 스케줄(베이배정+순서)을 사용자 NFP 엔진의
  warm-start/우선순위로 주입** → 사용자 엔진이 고밀도에서 더 낮은 Z1로 가는지. (.so 필요, 여기선 미검증)
- realizer feasible=False 는 래스터/크레인 모델 버그(프로토타입 한계) — 별건.
