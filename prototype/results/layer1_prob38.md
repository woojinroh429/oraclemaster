# Layer-1 스케줄 백본 검증 (prob_38, CP-SAT, 시간 넉넉히)

리서치가 SOTA로 지목한 "스케줄 마스터 + 패킹 서브" 분해의 Layer-1(스케줄 백본)을
prob_38(고밀도, 250블록, w1=13333, Z1 100% 지배)로 검증. 2D 기하를 용량자원으로 완화해
베이배정+시작시각을 CP-SAT로 최소화(가중목적).

## 결과

| 완화 | 목표 Z1 | objLB | 성격 |
|------|--------:|------:|------|
| area (면적 누적, 2D⟹면적 유효하한) | **177** | 93,331 | 하한(낙관, 100% 패킹 가정) |
| width (폭×시간 1D-strip) | **13,381** | 17,695 | 2D 실현가능 상한 |
| achieved (submit_v34 **fallback**, 45s) | 154,774 | — | 참고(C++없음, 불공정) |

CP-SAT 600s(area)/300s(width), FEASIBLE(최적 미증명, 좋은 스케줄 확보).

## 해석
- **면적은 병목이 아니다**: 시간 이동으로 면적부하 흡수 → area Z1=177. 밀도 2.58은
  "블록이 [release,due] 내내 점유" 가정의 과대추정이었음.
- **병목은 1D-폭 패킹 + 크레인**: width 완화 Z1=13,381.
- **width 목표는 2D 실현가능**: 폭합≤베이폭이면 y=0 좌측정렬로 겹침없이 배치 가능
  (블록높이≤베이높이인 한). → 진짜 최적 Z1 ∈ [177, 13,381], 대략 수천 규모.
- fallback 154,774는 서버 아님 → 격차 전부가 우리 이득은 아니나, **방어가능 하한이 수천**
  이라 고밀도 headroom이 큼(사용자 증상: ALNS가 고밀도 Z1 개선 못함 → 일치).

## 결정 & 다음
스케줄-우선 파이프라인 진행 확정. 다음: **width-완화 스케줄을 비트엔진으로 실현
(좌측정렬 + 크레인 체크) → 실제 feasible Z1 측정**. 13,381 근처 feasible이면 큰 개선 실증.
