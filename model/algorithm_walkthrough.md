# 알고리즘 실행 흐름 (한 스텝씩)

우리 알고리즘(`prototype/solve_colgen.py`)이 인스턴스 하나를 받아 해를 내기까지의 순서.
예시는 prob_1 (블록 100, 베이 2개: 51×20·54×18, 가중치 w1=29091 w2=7 w3=200).

## 결정해야 하는 것 (블록마다 4가지)
각 블록 i: **① 어느 베이 ② 어디에(x,y) ③ 어떤 배향 ④ 언제 반입/반출(EN,EX)**.
목적: `min w1·Z1(지연) + w2·Z2(부하불균형) + w3·Z3(선호손실)`.

---

## STEP 0. 입력 로드
`instance.json` → 베이 크기, 블록별 (release R, due D, processing P, workload L,
선호 S, 배향별 레이어 다각형).

## STEP 1. 래스터화 → 비트마스크 (엔진 준비)  [build_placements]
각 (블록, 배향, 베이)를 **딱 1회** shapely로 격자에 찍어:
- `occ[L]` = 레이어 L이 차지하는 셀들의 비트마스크(정수)
- `shadow[L]` = OR_{lev≤L} occ[lev]  (크레인 수직 그림자)

위치 이동은 shapely 재호출 없이 **비트 시프트** `mask << (dy·W+dx)`.
→ 이제 "겹치나?"는 `occ_a & occ_b == 0`, "크레인 되나?"는 `shadow & occ == 0` 한 줄.
(보수적 래스터라 마스크 안 겹치면 원본 다각형도 안 겹침 = 안전.)

동시에 Numba용으로 마스크를 uint64 워드 배열로 팩킹.

## STEP 2. greedy 시드 → feasible 1벌 확보  [greedy_seed]
블록을 **납기 빠른 순(EDD)**으로 정렬. 각 블록을 선호 베이의 빈 자리에 넣되,
비트 AND로 충돌 없는 위치를 찾고 크레인용 그림자를 예약. 안 되면 시간을 미룸(지연↑).
→ **100블록 무충돌 1벌**을 0.3초에 확보. 이게 뒤 정수해의 **INFEASIBLE 방지 + 최후 보루**.
(prob_1: greedy 지연 Z1=32 정도의 해)

## STEP 3. 초기 열(column) 풀 구성
- 각 블록에 대해 후보 배치 몇 개(분산된 위치) + greedy 해의 열을 **열 풀**에 넣음.
- 각 블록마다 **더미(미배치) 열**을 Big-M 비용으로 하나씩 — LP가 절대 안 터지게(인공변수).
  (Big-M은 실제비용의 ~10배로. 과대하면 LP 수치불안정.)

여기서 "열" = **하나의 완결된 배치 결정** = (블록, 베이, 배향, x, y, EN, EX).

## STEP 4. 열생성 루프 (알고리즘의 심장)  [반복]
좋은 배치(열)를 "필요한 것만" 계속 만들어 채우는 단계.

### 4a. 마스터 LP 풀기 (GLOP)
```
min Σ_c cost_c·λ_c
s.t. Σ_{c∈블록 i} λ_c = 1     ∀i        # 각 블록 한 배치
     Σ_{c∋셀 k} λ_c ≤ 1       ∀k        # 한 시공간 셀에 한 블록 (비겹침)
```
푸는 순간 **쌍대값(dual)**이 나옴: `π_i`(블록별), `μ_k`(셀별, ≤0 = 그 셀이 붐빔).

### 4b. Pricing — 새 열 찾기 (Numba)
각 블록의 **모든 후보 배치**에 대해 **감축비용**을 계산:
```
rc = cost − π_i − Σ_{셀∈배치} μ_k
```
- `cost` = 이 배치의 지연·선호 비용, `−Σμ` = 붐비는 셀 회피 압력.
- rc < 0 인 배치 = "지금 풀에 넣으면 목적이 더 좋아지는 열".
- 이 계산을 **uint64 비트 + Numba**로 초고속(100블록 라운드당 ~3초, 순수 Python은 수십 초).

### 4c. top-k + 다양성 필터(NMS)로 추가
rc<0 후보를 감축비용순 정렬 → **최선은 항상 채택**, 차선은 **이미 뽑은 열과 시공간 마스크
겹침 30% 초과면 스킵**(비트 AND). → 쌍둥이 열 대신 **서로 다른 알짜 대안**만 풀에 추가.

### 4d. 반복
음의 감축비용 열이 더 없을 때까지 4a~4c 반복 → **LP 최적**(Gurobi면 이 값이 하한=갭 근거).

## STEP 5. 정수 확정 (CP-SAT)  [생성된 열로]
LP는 λ가 분수일 수 있음. 이제 **정수**로:
```
각 블록 정확히 한 열 선택 (0/1),  한 셀에 한 블록(≤1),  목적에 Z2(Gmax−Gmin) 포함
```
CP-SAT가 생성된 열 안에서 최적 조합을 고름. greedy 해가 풀에 있어 **항상 feasible**.

## STEP 6. 정확검증 + 출력  [exact_check → solution.json]
고른 배치를 **shapely 원본 다각형**으로 재검사(컨테인먼트/같은레벨충돌/크레인/시간) →
위반 0이면 목적 재계산 후 제출형식 JSON 출력. (θ>0로 빡빡하게 넣었다면 여기서 겹친
소수만 밀어내는 repair.)

---

## 한 블록의 여정 (요약)
```
블록 i → [래스터화] occ/shadow 비트마스크
       → [greedy] 일단 어딘가 무충돌 배치(보루)
       → [pricing] 더 싼(rc<0) 배치들을 후보로 생성
       → [LP] 분수 비중 λ 로 최적 조합 탐색
       → [CP-SAT] 정수로 배치 1개 확정
       → [검증] 원본 다각형으로 실행가능 확인
       → 해에 (bay, x, y, orient, EN, EX) 기록
```

## 비트엔진·Numba가 쓰이는 지점
| 단계 | 비트/Numba 사용 |
|------|-----------------|
| STEP1 위치이동 | `mask << (dy·W+dx)` |
| STEP2 greedy 충돌 | `shadow & occ == 0` |
| STEP4b pricing | uint64 워드 + njit로 rc 일괄계산 |
| STEP4c NMS | `popcount(mask_a & mask_b)` 겹침률 |

## 크기별로 달라지는 부분 (현재/예정)
- **작은·중간(≤150)**: 위 STEP4~5 그대로 (거의 정확).
- **큰(250~300, 예정)**: STEP4~5 대신 **베이별 분해 + LNS(destroy/repair)** 로 교체.
  단 STEP1·2(엔진·greedy)와 STEP6(검증)은 공통.
