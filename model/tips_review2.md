# CG 튜닝 팁 ⑤⑥⑦ 검토 (우리 코드/실측 기준)

결론: **⑤ 매우 유용(이미 부분 구현 + 실측으로 status-4 원인 규명), ⑦ 유용(단서부),
⑥ 목표는 맞지만 방법 서술이 꼬임(정공법은 Z2 Gmax/Gmin 선형화).**

---

## ⑤ 인공변수(Big-M slack)로 feasibility 방어 — 유용, 이미 있음 + 진짜 원인 규명

- **이미 구현**: `solve_colgen.py`는 블록별 '더미(미배치) 열'을 Big-M 비용으로 갖고 있다
  (= Σλ + s_i = 1 의 인공변수). 팁의 메커니즘(양수 듀얼이 pricing을 압박)도 그대로 작동.
- **핵심 발견**: 원래 `BIG=1e9`가 **과대**해서, 셀 제약 12만개 퇴화 LP와 섞이며 GLOP가
  **status 4(ABNORMAL, 수치불안정)** 로 죽고 pricing이 1라운드에 멈췄다 → 정수 INFEASIBLE.
  팁 ⑤의 정신("Big-M은 유연성용")대로 **Big-M을 실제 열 최대비용의 10배(≈1.6e7)로 낮췄더니**:

  | 규모 | Big-M | LP 상태 | pricing | 정수해 | 검증 |
  |------|-------|---------|---------|--------|------|
  | 100블록 | 1e9 (과대) | status 4 (round1) | 1라운드 정지 | **INFEASIBLE** | - |
  | 50블록 | 1.6e7 (적정) | 정상, round4 최적 | 정상수렴 | **OPTIMAL** | 위반0, obj 23687 |
  | 100블록 | 1.6e7 (적정) | status 4 (round3) | 3라운드(899→1095열) | **INFEASIBLE** | - |

  → Big-M "크게"가 아니라 **"실제 비용을 지배하되 과하지 않게"** 가 정답. (팁이 방향은 맞고,
  우리 버그의 실제 원인을 정확히 겨눔.) **50블록은 이걸로 완전히 고쳐졌고**, 100블록은
  더 나아갔으나(1→3라운드) 아직 부족 — 즉 **⑤는 필요조건이지 충분조건이 아님**. 남은
  100블록 벽: (a) 셀 15만개 퇴화로 status-4 재발(→ LP 안정화/제약 축소 필요),
  (b) best-1 pricing으론 블록당 ~11열뿐 → 100개 무충돌 배치 불가(→ ⑦ top-k 필수).
  팁의 "기하급수적으로 빨라진다"는 과장.

## ⑥ Z2 선형화 시 '더미/완충 열 기만 트릭' — 목표는 맞으나 방법 서술이 꼬임

- 목표(Z2를 LP에 넣어 균형 유도)는 옳다. 실제로 지금 50블록 obj=23687의 대부분이 Z2=698
  (imbalance)라, Z2가 LP에 없어서 CG가 불균형 열만 만든 게 확인된다.
- 그러나 **정공법은 '완충 열 주입'이 아니라 Gmax/Gmin 보조변수 선형화**다:
  ```
  G_j = Σ_{c in bay j} u_j * workload_c * λ_c
  Gmax >= G_j,  Gmin <= G_j,   목적에 + w2*(Gmax - Gmin)
  ```
  열은 항상 '실제 실행가능 배치'여야 하며(공간을 억지로 비우는 buffer 열은 실행가능성/의미
  훼손), 균형은 선택된 실열들의 bay 조합으로 달성된다. '완충 열'은 이 문제에서 불필요/위험.
- 요지: ⑥의 **의도(Z2 steering)는 채택, 서술된 방법(buffer column)은 폐기**, 표준 선형화 사용.

## ⑦ 듀얼 기반 다양성 필터(NMS/MIS) — 유용, 단 '최선 열은 항상 유지'

- 지금은 라운드당 **블록별 best-1 열**만 추가 → 100블록에서 풀이 너무 얇아 정수 INFEASIBLE의
  한 원인. 팁대로 **top-k + 마스크겹침 필터**로 다양성을 주면 풀 품질이 오른다.
- 방법: pricing이 감축비용순 후보를 뽑되, 이미 채택한 열과 **3D 비트마스크 AND 겹침이 임계
  (예 30%) 초과면 스킵**(비트연산으로 즉시). → 마스터에 '서로 겹치지 않는 알짜 대안'만 공급.
- **단서**: (1) 감축비용 최선 열은 겹치더라도 반드시 유지(LP가 원하는 열). NMS는 '차선들'에만.
  (2) 다양성은 라운드 수를 줄이지 마스터 행수 자체는 여전히 증가 — 각 열이 더 유용해질 뿐.
  (3) "초 단위로 깎인다"는 과장이나, 라운드/풀 효율 개선은 실질적.

## 우리 실측이 가리키는 우선순위 (증거 기반)

1. **⑤ Big-M 적정화 = 즉효** (이미 반영, 50블록 INFEASIBLE→OPTIMAL 로 실증).
2. **⑦ top-k + 다양성 필터** = 100블록 정수 feasibility 확보의 열쇠(풀 두께).
3. **⑥ Z2 Gmax/Gmin 선형화** = obj를 1499 방향으로 견인(현재 imbalance 지배 해소).
4. **Numba pricing**(앞서 9x 측정) = 위 ⑦를 100블록에서 시간 내 돌리는 엔진.

즉 팁 3개 중 ⑤는 이미 값을 했고, ⑦은 다음 최우선, ⑥은 방법만 바로잡아 채택.
