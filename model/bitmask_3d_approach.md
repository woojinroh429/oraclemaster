# 복셀 격자 + 비트논리 기반 정확 수리계획 (Set-Partitioning / Branch-and-Price)

핵심 주장: 문제를 **3D 복셀 격자**로 이산화하고 블록 점유를 **비트셋(bitset)** 으로
표현하면,
1. 블록간 비겹침·크레인 제약이 **big-M/NFP disjunction 없이** 순수 **집합분할(set-partitioning)**
   선형제약으로 바뀌고,
2. 기하 판정(충돌·크레인·가지치기)이 **비트 AND / popcount** 한두 번으로 끝나며,
3. 최적성은 **열생성/분지가격**으로 보장된다(휴리스틱 아님).

즉 "휴리스틱 대신 최대한 수리계획으로"라는 목표에 정확히 부합한다.

> 표기: ASCII. 비트연산 & = AND, | = OR, ^ = XOR, popcount = 켜진 비트 수.

---

## 1. 왜 2D가 아니라 3D(복셀)인가

- 블록은 원래 **레이어(높이 z)** 를 가진 3D 물체다. 같은레벨 충돌·크레인 수직간섭은
  본질적으로 3D 관계다.
- 공간을 (x, y, k) 복셀 격자로 두면:
  - **같은레벨 충돌회피** = 같은 k 평면에서 두 마스크가 겹치지 않음 → 3D 마스크 AND == 0.
  - **크레인 제약**(l1의 위쪽 l2>=l1 이 비어야 함) = 수직 그림자 마스크 AND == 0.
    → 2D로는 표현이 번거롭던 제약이 **3D에서 단일 비트연산**이 된다. (이게 3D 확장의 핵심 이득)

## 2. 격자·비트마스크 정의

### 2.1 복셀 격자
- 베이 j: `Wj x Hj` 셀, 레이어 레벨 k = 1..Kmax. → 베이당 복셀 수 `V_j = Wj*Hj*Kmax`.
  (예: 140 x 29 x 4 ~ 16k 복셀 → 비트셋 2KB.)
- 위치 x,y 는 정수(평가서버가 반올림) → 단위격자가 자연스럽다. 정밀 배치가 필요하면
  1/2, 1/4 서브격자로 해상도만 올린다(비트 수만 증가).

### 2.2 블록 점유 마스크 (사전계산)
각 (블록 i, 배향 o, 위치 (x,y)) 에 대해, 레이어 다각형을 **보수적 래스터화**:
셀 내부를 다각형이 조금이라도 침범하면 그 복셀을 1로.

```
B[i,o,x,y]  :=  블록 i를 배향 o로 (x,y)에 놓았을 때 점유하는 복셀들의 비트셋
```
보수적 래스터화 => "마스크가 안 겹치면 실제 다각형도 안 겹침" (원문제에 대해 안전/보수적).
해상도를 올릴수록 근사손실(가장자리 반 셀)이 0에 수렴 → 사실상 정확.

### 2.3 크레인 수직 그림자 마스크 (사전계산)
블록 i를 수직으로 넣거나 빼려면, 점유 복셀의 **바로 위 기둥**이 비어야 한다:

```
Bup[i,o,x,y] := { (x',y',k') :  (x',y',k) in B[i,o,x,y] 이고  k' >= k }
```
즉 각 점유 (x,y)에서 그 레벨 이상 전부를 위로 쓸어담은 마스크. 크레인 가능 <=>
`Bup[i,o,x,y] & (그 순간 다른 블록들의 점유마스크) == 0`.

## 3. 순수 집합분할 MIP (big-M 없음)

### 3.1 열(column) = 하나의 완전한 배치패턴
```
c = (bay j, 배향 o, 위치 x,y, 반입 EN, 반출 EX)      # 블록 i의 후보 패턴
```
패턴 c는 **시공간 복셀 집합**을 점유한다:
```
occ(c) = { (j, x', y', k, t) :  (x',y',k) in B[i,o,x,y],  t in [EN, EX) }
```

### 3.2 변수·목적·제약
```
결정변수:
  p[i,c] in {0,1}     # 블록 i가 패턴 c를 사용

(P1) 배정:      sum_c p[i,c] = 1                      for all i        # 각 블록 정확히 1패턴
(P2) 시공간팩킹: sum_{i,c : cell in occ(c)} p[i,c] <= 1  for every space-time cell (j,x,y,k,t)
                                                                     # 한 복셀·한 시각에 1블록
(P3) 크레인:    반입/반출 순간의 수직그림자도 팩킹에 포함(아래 3.3)

목적:  min  w1*sum_i T_i(c)  +  w2*Z2  +  w3*sum(선호손실(c))
       - T_i(c) = max(0, EX(c) - D_i)  : 패턴 c에 내재된 상수(패턴이 EN/EX를 고정)
       - 선호손실(c) = Smax_i - S_{i, bay(c)}          : 패턴에 내재
       - Z2(부하불균형)은 배정 bay(c)로부터 (C13)-(C15)와 동일하게 선형화
```
**(P2)만으로 같은레벨 충돌회피가 정확히 표현된다.** big-M도, 분리방향 이진도, NFP도
전혀 없다 — 셀 용량 1의 순수 set-packing.

### 3.3 크레인을 팩킹에 녹이기
반입은 EN(c) 시각, 반출은 EX(c)-1 시각에 일어난다. 그 순간 수직그림자 `Bup`가 다른
블록과 겹치면 안 되므로, 그 두 순간에 한해 occ에 그림자를 더한 **확장 점유**를 쓴다:

```
occ+(c) = occ(c)
        ∪ { (j, x', y', k, EN(c))   : (x',y',k) in Bup[i,o,x,y] }   # 반입 순간 위쪽 청소
        ∪ { (j, x', y', k, EX(c)-1) : (x',y',k) in Bup[i,o,x,y] }   # 반출 순간 위쪽 청소
```
그리고 (P2)를 occ+ 로 부과. 그러면 크레인 제약도 **같은 set-packing 안**에 정확히 들어간다.
(방향성/순서는 EN,EX 값이 패턴에 박혀 있어 시각 인덱스로 자동 구분된다.)

## 4. 비트논리 연산이 어디서 가속하나

| 작업 | 비트연산 |
|------|----------|
| 두 패턴 c, c' 공간충돌? | `B_c & B_c' != 0` (레벨·평면 자동 포함) |
| 크레인 가능? | `Bup_c & (거주블록 OR누적) == 0` |
| 열생성 pricing (감축비용) | 셀 쌍대값을 비트평면에 얹고 `popcount(B_c & dualmask)` 로 즉시 합산 |
| 가지치기(지배열 제거) | `B_c` 가 다른 열에 포함되는지 `B_c & ~B_c'` 로 판정 |
| 하루 배치 가능성 | 후보 마스크들 순차 OR 누적, `누적 & 새마스크 == 0` 이면 배치 |

Python 큰정수(임의정밀 비트) / numpy uint64 배열 / C++ std::bitset 로 구현. 평가서버는
numba·cython·4코어 가용이라 충분히 빠르다. 인터넷·GPU 불필요.

## 5. 열 폭발 대응 = 열생성 / 분지가격 (여전히 정확)

- 후보 패턴 수 = (위치 Wj*Hj) x (배향 O) x (EN,EX 조합) → 전부 나열하면 폭발.
- **열생성(column generation)**: 모든 패턴을 만들지 않는다. 쌍대값이 주어지면 각 블록의
  **최적 패턴 하나**만 pricing으로 생성(비트 popcount로 셀 쌍대합 계산). 감축비용이 음수인
  패턴이 없을 때까지 반복 → LP 완화 최적.
- **분지가격(branch-and-price)**: 정수해까지 분지. → **휴리스틱 아님, 최적성 보장.**
- 시간(EN,EX)은 나열하지 않고 pricing이 지연/쌍대 압력을 보고 최적으로 선택.

## 6. 정확도·메모리 트레이드오프 (정직하게)

| 항목 | 내용 |
|------|------|
| 래스터화 근사 | 보수적 래스터화는 안전(겹침 오판 없음)하나 가장자리 반 셀만큼 조밀도 손실. 해상도↑로 임의로 줄임 |
| 정수 위치 | 평가서버가 x,y 반올림 → 단위격자면 근사손실 대부분 흡수 |
| 복셀 수 | 베이당 ~1.6만, 시공간까지 곱하면 큼. 단 (P2) 제약은 **희소**하고 필요한 셀만 지연생성 가능 |
| 열 수 | 폭발하지만 **생성 안 함** — 열생성으로 필요한 것만 |
| 대안(경량) | 시간은 EN/EX 정수변수로 두고 **공간만 비트마스크로 충돌그래프** 생성 → set-packing 대신
  충돌쌍 clique 제약. 열생성 없이도 중형 인스턴스 가능 |

## 7. 요약 — 이 접근의 위치

```
AABB (v1)         : 쉬움, 근사 커서 지연↑ (품질 낮음)
NFP disjunction   : 정확하나 big-M 이진 폭증, 브랜치 폭발
복셀+비트 set-pack : 정확(해상도로 조절) + big-M 제거 + 비트연산 가속 + 분지가격 최적성
                    => "휴리스틱 없이 수리계획으로" 목표에 가장 부합
```
권장 로드맵: (1) 보수적 래스터화로 `B, Bup` 사전계산 → (2) 소규모 인스턴스에서 완전
set-packing MIP를 직접 풀어 타당성/품질 확인 → (3) 열생성/분지가격으로 n=100~300 확장 →
(4) 해상도·시간창 프루닝으로 크기 조절.
