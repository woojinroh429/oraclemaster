# 아키텍처 — 3D 비트 엔진 위의 매트휴리스틱 (크기별 2트랙)

핵심 원리: **하나의 3D 비트 엔진(substrate)** 위에, 인스턴스 크기에 따라
**정확-지향 CG(작은·중간)** 또는 **LNS 매트휴리스틱(큰)** 트랙을 얹는다.
어떤 크기든 **greedy 시드가 feasibility를 보장**하고, 최종은 **정확검증 게이트**를 통과한다.

```
instance.json
   │  ① PREPROCESS (rasterize θ)
   ▼
occ/shadow 비트마스크 ──────────────┐
   │  ② greedy 시드 (엔진 호출)      │  (엔진은 아래 모든 단계가 호출)
   ▼                               │
feasible 1벌 (fallback)            │
   │                               │
   ├─(n≲150)→ TRACK A: CG+pricing+정수화 ──┐

## 왜 이 구조인가 (설계 근거)

- **엔진과 전략의 분리**: 충돌·크레인·pricing을 전부 비트연산 한 층으로 모아, 위의 어떤
  전략(CG든 LNS든)도 같은 초고속 프리미티브를 호출 → 코드 재사용 + 속도.
- **feasibility 먼저**: greedy 시드가 크기 무관 무충돌 1벌을 보장 → 대회 점수의 전제(feasible)
  를 항상 확보. 최적화는 그 위에서 "개선"만 담당.
- **크기별 트랙**: 작은 건 CG로 거의 정확(+갭), 큰 건 분해+LNS로 feasible+최선노력.
  둘 다 3D 엔진을 공유하므로 하부는 하나.
- **Gurobi 위치**: TRACK A의 마스터 LP·정수화, TRACK B의 repair 부분최적 — 모두 "부분/중형"
  문제에만 투입(통짜 300블록 아님). 라이선스 오면 GLOP/CP-SAT 자리를 그대로 대체.
- **최종 게이트**: 제출 전 대회 `utils.check_feasibility()`로 반드시 확인(−1점 방지).
